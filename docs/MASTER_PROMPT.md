## 2. Non-negotiables

1. **Approved icon.** `playstore-icon-512.png` in the repository root **is the approved Misty OS icon**.
   - It must be the source of every Android launcher layer (legacy, round, adaptive foreground/background).
   - Do **not** redesign, redraw, recolour, re-shadow, or replace it with generic Flutter art, and do not keep a procedural "cloud generator" as the icon source.
   - Verify the built APK: `aapt2 dump badging` shows `application: label='Misty OS'` and the mipmap PNGs are byte-derivable from the approved 512 art.
2. **One icon registry.** A single `AppId → asset` mapping feeds Dock, Launchpad, Spotlight, Finder, window title bar, app switcher and notifications. No screen may invent its own icon.
3. **No placeholder apps presented as apps.** Anything in the Dock/Launchpad either works or is visibly marked as unavailable. A registered-but-dead app is a bug.
4. **No white windows.** Every window renders real content, a loading state, or an error state with a Retry action. Never a blank surface.
5. **Never break the guest.** Do not remove PRoot, Xvfb, x11vnc, noVNC, Chromium, Firefox, OpenCode, qBittorrent, or the pre-baked rootfs.
6. **Do not disable Chromium's software rasterizer** as a "speed fix". It is often the only working path under Xvfb.
7. **Do not hijack the Android Home gesture.** The Dock must never claim the bottom system-gesture strip.
8. **Branding.** User-visible strings say Misty OS. Internal identifiers (`micro_os`, `com.matthewcodergamer.micro_os`, `microos/rootfs`, `/root/.microos`, `microos-run`) stay unchanged.
9. **Scope discipline.** Fix the architecture before adding cosmetics. Small, reviewable commits. No repo-wide reformatting.

## 3. Work order (do not parallelise these)

### P0 — Application launching and white screens (blocking)

Audit and fix, in this order:

1. `lib/ui/desktop_screen.dart` — window mounting.
   - `WindowFrame` returns an `AnimatedPositioned`/`Positioned`; it **must be a direct child of the `Stack`**. A `RepaintBoundary` or any other widget between the `Stack` and the `Positioned` breaks `StackParentData` and produces full-bleed, mis-stacked or invisible windows.
   - Wrap the *content inside* `WindowFrame` with `RepaintBoundary`, never the positioned widget itself.
2. `lib/state/desktop_state.dart`
   - `open()` must never produce a zero/negative rect. Guard `_screen == Size.zero` on the first frames, clamp min size (≥ 280×180), clamp into the usable area.
   - `syncToScreen()` must re-clamp **every** window, not only maximized/pinned ones.
   - `isCompact`/`_maxRect` must be identical for portrait and for landscape short screens.
3. `lib/ui/window_frame.dart`
   - Never animate `Opacity`/`Transform` over a `PlatformView` (WebView). That is a documented cause of white/blipped WebView layers on Android. Use a static layout for platform views; animate only the chrome.
   - Add `ClipRect` + `RepaintBoundary` around window content.
4. `lib/ui/apps/desktop_session_app.dart` (noVNC / Chromium / Firefox)
   - Show a real loading state until `document.body.innerText` reports `Connected`.
   - If the WebView fails to attach, show an error card with **Retry** and **Open runtime log** — never leave the dark/white rectangle.
   - `setBackgroundColor` must match the window body, not white.
5. Global error handling in `lib/main.dart`
   - Keep `ErrorWidget.builder`, improve it: friendly message + Retry in release, full exception + stack in debug.
   - Route `FlutterError.onError` and `PlatformDispatcher.onError` through one reporter that also appends to the runtime log so Settings → Runtime log can show it.

**Acceptance:** open every app from Dock, Launchpad, Spotlight and the menu bar; each renders, is interactive, and closes without freezing. Log the result per app.

### P1 — Branding + approved launcher icon

- Sweep `MicroOS`/`microOS` in visible strings (default user name, comments that surface in UI, README/release notes). Keep internal ids.
- Replace `tool/generate_launcher_icon.py` with a script that derives **all** layers from `playstore-icon-512.png` (upscale with Lanczos; background = edge-sampled gradient so the adaptive mask never shows a letterbox).
- `flutter_launcher_icons.yaml`: `image_path: playstore-icon-512.png`, adaptive foreground/background from the derived layers, `adaptive_icon_foreground_inset: 0`.
- Verify in the APK, not in the repo.

### P2 — One icon system

- Central registry: `AppId → asset path`, with a documented fallback for apps that have no approved artwork yet.
- Dock, Launchpad, Spotlight, Finder sidebar/rows, window title bar and app switcher all read that registry.
- Icons keep aspect ratio (`BoxFit.cover` inside a squircle clip), stay crisp (`cacheWidth ≈ 2× logical size`), and never stretch.
- Portrait Dock = 5 primary apps: **Finder, Browser (Safari), Terminal, AI Hub (OpenCode), Settings**. Everything else lives in Launchpad. Landscape = compact set.

### P3 — Dock geometry and feel (portrait + landscape)

- Icons must be **centred** when they fit, and horizontally scrollable when they do not. (`SingleChildScrollView` + `ConstrainedBox(minWidth: viewport)` + `MainAxisAlignment.center`.)
- Never overflow the screen; respect `MediaQuery.viewPadding` and `systemGestureInsets`.
- Animations: cosine magnification, spring-like scale, press feedback, running indicator, open/close transition, frosted glass. Keep `RepaintBoundary`; keep blur ≤ 15σ on mobile.
- Long-press a running icon = close its windows.

### P4 — Login (1:1 macOS)

- Full-screen wallpaper, blurred/dimmed scrim.
- Clock + date at the top.
- Centred avatar, user name, and a clear affordance to begin.
- Tap **or swipe up** → the account panel slides up and the password field fades/slides in. Enter-to-submit. Password visibility toggle.
- Wrong password: the panel **shakes** (damped sine), error appears, field clears, haptic fires.
- Correct password: unlock + cross-fade into the desktop.
- Never auto-unlock. Never bypass the lock when secure storage is unavailable — fail closed with a readable message.
- Keep the existing `flutter_secure_storage` mechanism.

### P5 — Real applications

**Finder** (`lib/ui/apps/files_app.dart`)
- Real guest paths: `/root`, `/root/Downloads`, `/root/Documents`, `/root/Desktop`, `/mnt/android`, `/mnt/android/Download`, `/`.
- Create folder/file, rename, delete (confirm), copy, move, multi-select, search, details, sorting, type icons, folder previews.
- Real filesystem operations through the guest shell; never simulate.
- `/mnt/android/Download` is the shared Android Download folder and must be writable by the guest, with a `~/Downloads` shortcut.

**Terminal** (`lib/ui/apps/terminal_app.dart`)
- Real PTY (`flutter_pty`), tabs, new/close/switch, scrollback, copy/paste, keyboard shortcuts, resize on keyboard open/close without desktop flicker.

**AI Hub / OpenCode**
- Real `opencode` in the guest; verify editing, running, `git`, GitHub auth (`GH_TOKEN`), Hugging Face auth (`HF_TOKEN`), Playwright.
- Projects persist across restarts (they live in the rootfs, not in memory).

**Browser**
- Chromium + Firefox launch through `microos-browse`; downloads land in `/mnt/android/Download`.
- Address bar, tabs, back/forward/reload, download manager, download notification.

**Torrents / VPN**
- qBittorrent-nox is pre-installed and started by `/root/.microos/start-torrent.sh`; confirm the Torrents app reaches `127.0.0.1:8080` and that magnet/torrent links from the browser can be handed to it.
- WireGuard/openvpn must be genuinely usable or clearly absent — do not ship a dead VPN tile.

### P6 — Settings, Control Center, Spotlight, wallpapers

- Settings: desktop/dock, speech, GitHub, Hugging Face, Linux, terminal, browser, users/login, About — every control must change persistent state.
- Control Center: Wi-Fi, battery, RAM, ZRAM, Linux status. No decorative toggles.
- Spotlight: search apps, open with Return; **no yellow double underlines** (text must always sit under a `DefaultTextStyle` with `decoration: TextDecoration.none`).
- Desktop: **long-press empty desktop → change wallpaper**, persisted, with the Misty option-3 sky and the Big Sur asset. `BoxFit.cover`, decoded at display resolution, no stretching.

### P7 — Performance, polish, glitches

- One wallpaper decode per resolution change; capped `cacheWidth`.
- No per-frame rebuild of the whole shell: isolate with `ValueListenableBuilder`/`RepaintBoundary`.
- Keyboard open/close must not flash the desktop: reserve insets in `DesktopState.syncToScreen`, don't rebuild the wallpaper.
- No overflow banners, clipped Dock, stretched wallpaper, misaligned title bars, or double underlines.
- Keep blur/shadow budgets mobile-sized. Test on a 4 GB device class.
